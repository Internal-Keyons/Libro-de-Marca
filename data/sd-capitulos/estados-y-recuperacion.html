KYN-SDI-PAT-007Ruta de salida

Salida ante errores que impiden continuar

Se aplica cuando un error detiene la tarea: la interfaz explica y ofrece otra forma de seguir.

Ante un error que impide continuar, la interfaz DEBE ofrecer una alternativa viable o explicar claramente qué impide la recuperación.⁠

Qué se diceSalida
Red o servidorQue la acción no se completó y si los datos se conservaron.Reintentar.
Servicio externo o IAQue el servicio no respondió.Una ruta manual en el mismo lugar (desde UIX-023).
PermisoQue no tiene acceso, sin revelar datos.Volver o solicitar acceso.
Datos inválidosQué dato y cómo corregirlo.El campo, con su mensaje.
KYN-SDI-PAT-008Reversibilidad

Deshacer y restaurar

Se aplica a las acciones que se pueden revertir: deshacer está donde ocurrió la acción.

Las acciones reversibles DEBERÍAN ofrecer una opción de deshacer o restaurar cuando resulte técnica y funcionalmente apropiado.⁠

(Deshacer)

Aviso breve, sin bloquear la pantalla, con «Deshacer» durante un tiempo suficiente; se anuncia con role="status".

(Restaurar)

Lo eliminado pasa a una papelera desde donde se recupera, cuando el producto lo permite.

Verificación

Se ejecuta una acción reversible y se deshace. Resultado esperado: el estado anterior vuelve completo.

KYN-SDI-PAT-009Persistencia

Datos válidos que sobreviven a un fallo

Se aplica cuando una operación falla a mitad de camino: lo válido se conserva para reintentar.

Un fallo NO DEBE eliminar información válida que pueda conservarse de forma segura.⁠

(Qué se conserva)

Datos escritos, filtros, selección y posición, mientras sea seguro.

(Qué no se conserva)

Datos de pago y contraseñas, por seguridad.

KYN-SDI-PAT-010Estados vacíos y de espera

Estados vacíos y de espera

Se aplica a listas sin contenido y a operaciones que tardan: ninguna pantalla queda sin explicación.

Un estado vacío DEBE explicar por qué no hay contenido y ofrecer el siguiente paso.⁠

Una espera DEBE indicar que el sistema está trabajando.⁠

Qué muestraAcción
Vacío por primera vezPara qué sirve el espacio: «Aún no hay solicitudes».Crear la primera.
Vacío por filtrosQue los filtros no tienen coincidencias.Quitar filtros.
Espera breveUn indicador en el lugar de la acción.—
Espera largaQué está haciendo el sistema y, si se conoce, el avance.Cancelar, si se puede.
Notas técnicas
Anuncio
Los cambios de estado se anuncian en una región role="status", sin mover el foco.
Umbral
El tiempo a partir del cual una espera es larga es una hipótesis que hay que validar (UIX-021 proponía 400 ms y 3 s).
Verificación
Cuatro casos
Se fuerzan una lista vacía por primera vez, una búsqueda vacía, una espera corta y una espera larga. Resultado esperado: ninguno queda en blanco ni sin una acción posible.
Lector de pantalla
Se provoca una espera con un lector de pantalla activo. Resultado esperado: se anuncia que el sistema está trabajando y, después, el resultado.
18Ejemplo de aplicación

Un pago que no se verificó

Si la verificación automática de un pago falla, la persona puede adjuntar el comprobante en el mismo lugar.

18Validación

Validación del capítulo

El capítulo se comprueba simulando errores de red, de validación y de operación, y comprobando la recuperación.

(Ruta de salida)

Se simulan errores de red, de servicio, de permiso y de datos. Resultado esperado: cada uno muestra qué pasó y ofrece su salida.

(Persistencia)

Se fuerza un fallo a mitad de una tarea y se reintenta. Resultado esperado: los datos válidos siguen ahí.
